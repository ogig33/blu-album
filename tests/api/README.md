# BluAlbum – API tests (Bruno)

Contract tests for every player request the app uses and for the endpoints of the API reference [`docs/bluos-api.md`](../../docs/bluos-api.md). They check the **structure** of the answers (elements, attributes), not concrete albums or numbers.

## Setup
1. Bruno: *Open Collection* → choose this folder.
2. Select the environment **Home** (top right). Set `host` to the IP address of your player.
3. Collection settings → *JavaScript sandbox* → **Developer mode** (needed for writing fixtures and for the requests that ask the player several times). Or set `saveFixtures` to `false`.
4. `runManual` stays `false`; set it to `true` only to run the manual folder.

## Before a run
- A queue with at least 2 entries, playing or paused (not a radio stream).
- At least one preset.
- A USB drive is optional; USB requests are skipped without one.
- Optional: at least one favourite song and more than 10 queue entries; W17 and W21 are skipped otherwise.

## Run the whole suite (e.g. after a firmware update)
Run the **whole collection** in the Runner (or `bru run -r --env Home` in this folder). The folders run in order:

| Folder | What it does | Effect on the player |
|---|---|---|
| **1 Read (safe)** | Every read request of the app (A01–A30), album details, the variants the app uses and new candidates (E01–E21, E23–E48), the reference endpoints that only read (V01–V55, including the whole settings tree and the app screens `/ui/…`) | none |
| **2 Write (changes the player)** | Every command of the app (C01–C47), queue, playback and favourite commands of the reference (W01–W33), settings, playlist and name commands of the reference (S01–S52) | playback is interrupted; queue, position, pause state, volume, repeat, favourite and every changed setting are restored, test playlists deleted |
| **3 Manual (run on purpose)** | Doorbell, library rescan, test preset, reboot, playlist restore, clear history, statistics, rebuild index, UpdateDNS, radio favourites (URL, TuneIn, Airable), playurl (M01–M34) | skipped unless `runManual = true` |

After a firmware update, compare `23-api-version.xml` and `24-bluos-version.xml` in `fixtures/` with the versions in the reference and look at the failed tests.

CLI: `npm i -g @usebruno/cli`, then in this folder `bru run -r --env Home` (whole suite) or `bru run "1 Read (safe)" --env Home` (one folder).

## Folders in detail

Request URLs are built by the scripts with `encodeURIComponent`; such requests set `settings { encodeUrl: false }`, otherwise Bruno encodes them a second time and the player answers HTTP 400.

Every request has a unique prefix: **A** app reads, **E** album details / new variants, **V** reference reads (folder 1); **C** app commands, **W** queue and playback, **S** settings and playlists (folder 2); **M** manual (folder 3). Fixture files of the app requests keep the number without the letter (`A19 Status` → `19-status.xml`).

### 1 Read (safe)
- **A01–A30** (app): every read request of the app (A27: listening mode, `/audioPreset`; A28: track list of the first BluOS playlist, as the playlist popup asks it; A29: library playlists of the library menu; A30: track list of the first library playlist, skipped without one). Later requests use keys found by earlier ones, so run the folder in order.
- **E01–E21, E23–E48**: more details of the first album (library album, songs, track context menu, technical info, track info) and the songs of a USB album (E07, E08). E01–E08 check only HTTP 200, the answers go to `fixtures/explore-*.xml`. E09–E13 check variants the app uses: the album track list without context menus (E09) and the albums of an artist through the artist's browse menu, for the library (E10, E11) and USB (E12, E13). E14–E21 check candidates that are not used yet: the albums of a genre without sections through `/ui/browseGrouped` with the genre album list as url, as the BluOS app asks them (E14 library, E15 + E16 USB; the browse key `Album/…genre=…` and `/library/v1/Albums?genre=…` without section answered empty); the artist list of the first favourite and whether it marks the favourite (E17); the album section of the first favourite without context menus, which must keep the favourite state (E18); New (E19), Favourites (E20) and a quality section (E21) as browse lists with the player's play URLs and context menus. E23 checks whether `/Status` names the listening mode of A27 (it does not). E24 checks that a cover from `/Artwork` may be read with `fetch()` from a page opened as a file (`Access-Control-Allow-Origin: *`; the app loads covers this way because Firefox upgrades plain image URLs to https). E25 and E26 ask the track list of the first favourite with a German and an English `Accept-Language`: German answers some albums with an empty menu (player bug, seen for "The Wall HiRes"; E25 only records the track count), English the tracks (E26, what the app sends). Answers go to `fixtures/explore-14…23-*.xml`, counts and paging to the console. New API variants are tried here first. E27–E30 check which tags `/library/v1/Songs` gives: the first composer's album (`composer`, `discno`) and a sampler with the album artist "Various" (`albumartist`, `compilation`); the console lists the elements per song, answers go to `fixtures/explore-27…30-*.xml`. E31 asks the first album cover with `width` and `height` 3000, as the album popup and the full-screen view do, and checks HTTP 200, an image and the CORS header. The pixel size cannot be read in Bruno (the body arrives as UTF-8 text, chunked without Content-Length); check it with curl: the original image (at most 3000 px) when "Optimize Artwork" is off and the index was rebuilt, else 600 px; a cover file larger than 600 KB gives the grey placeholder (494 × 494 px, 17829 bytes). E32 finds the first song with `discno` 2 or higher in the library search and asks the track list of its album (`/Browse`, as the album popup does): it checks that the tracks come in the order of the songs of `/library/v1/Songs`, so the disc of a track is the `discno` of the song at the same position; the console lists disc and track per entry, the answer goes to `fixtures/explore-32-multi-disc-album-tracks.xml`. E33 reads `song` of `/Status` and asks that queue entry (`/Playlist?start=<song>&end=<song>`, as the full-screen view does for the year): exactly one song, the same title as `title1`, a `<date>` with the year; skipped when nothing plays from the queue; the answer goes to `fixtures/explore-33-queue-entry-playing.xml`. E34–E36 check candidates for a decade filter: library section A of `/library/v1/Albums` without a filter, where every album with a year tag has `date` with four digits (E34, the console counts albums per decade); the album list of the BluOS app sorted by decade (`/ui/browseGrouped` with `sort=decade` inside `url`), whose index has one contiguous entry per decade adding up to the total (E35); and a jump straight to the last decade with `listContinuation=<offset>` (E36). Answers go to `fixtures/explore-34…36-*.xml`. E37 checks which tags the albums list of the player's search (`/Browse` with the search key, link "Albums", all sections) matches, for the album of the first composer: a track artist finds the album, a song title and a composer do not; a term is only used when it does not occur in the album title, the album artist or a track artist of the album; the console names the terms, the answer goes to `fixtures/explore-37-search-track-artist-albums.xml`. E38 follows a composer found by the search, as the app does: search for the first composer of the library, its entry in the composers list, its browse menu, its link "Albums"; it checks the albums list (play URLs, context menus) and that it contains the first album of `/library/v1/Albums?composer=`; the answer goes to `fixtures/explore-38-search-composer-albums.xml`. E39 checks whether a song of the search leads to its album: search for a word of the first song's title, link "Songs", first song, its context menu; the song has no browse key (only a context menu key with album and track artist, text2 "artist • album", play URL by file) and its context menu has no link to the album; the answer goes to `fixtures/explore-39-search-song-context-menu.xml`. E40 checks that the search does not find an album by its album artist: album artists from the sectioned artists list of the library menu (`Various` first), the first one with an album whose title and track artists do not contain the name; the search for that name must not list the album, while the albums of the album artist (link "Albums" of its browse menu) contain it; the console names the album and counts the albums of the album artist and the hits of the search; the answer goes to `fixtures/explore-40-search-album-artist.xml`. E41 (library) and E42 (USB, skipped without one) check the decade index the app uses for the decade chips (`/library/v1/Albums` with `section=all&length=1&sort=decade`, instead of the app screen of E35): only sections named by decade, no albums, and the same decades and counts as the years (`date`) of the A-Z sections; the answers go to `fixtures/explore-41…42-*.xml`. E43–E46 check `section=all` and an MQA bug of the player: all albums and the three quality lists in one request equal the lists per section and the count of the index, which also shows a cut-off in a large library, and `category`, `recent`, `composer` are ignored with it (E43, library and USB); genre lists in one request equal the genre's `/Browse` lists, and the URLs built like `libAlbum()` of the app equal the player's (E44, the first genre and the first with an encoded character); albums of songs with `mqaBrowse` are in no quality list (E45, skipped without such songs; a failure after a firmware update may mean that the bug is fixed); all album artists in one request, while Songs and Composers answer only the index (E46). Answers go to `fixtures/explore-43…46-*.xml`. E47 and E48 check which filters combine and which tags are no filter, for the album artist with the most albums and a genre with some of its albums: on `/library/v1/Albums` `genre` and `quality` narrow `artist`, `category` and `recent` (`recent` lists the 1000 newest albums), `quality` narrows `expr`, `expr` wins over `artist` and `artist` over `category`, and year, label, format and other tags are ignored (E47); on `/library/v1/Songs` `artist` matches album or track artist and combines with `genre` and `quality`, `composer` wins over `artist`, `expr` finds titles only; `/library/v1/Artists` takes `expr` and `genre`, `/library/v1/Composers` ignores `artist` (E48, uses the artist and genre of E47). Answers go to `fixtures/explore-47…48-*.xml`.
- **V01–V12**: reference endpoints that only read: `/SyncStatus`, `/Presets`, `/RadioBrowse?service=Capture`, `/Services`, `/Settings?id=audio`, `/Settings?id=capture&schemaVersion=32`, `/sharecfg` (port 80), the first new library album with `/AddToPlaylistOptions` and `/library/v1/Playlists` (imported, favourites). V12 reads the whole settings tree (`/Settings?schemaVersion=36` and every menu page, no buttons) into `fixtures/settings/` with a list of all endpoints found in `_summary.txt`. V13–V20 read the screens of the BluOS app (`/ui/Home`, `/ui/Sources`, `/ui/Queue`, `/ui/presets`, `/ui/myPlaylistsRow`, `/ui/BrowseObjects`, `/ui/browseContext`, `/ui/ContextMenu`), V21–V25 `/ui/Favourites`, `/ui/RecentlyPlayed`, `/ui/queueItemCM`, `/AddToPlaylistOptions?saveQueue=1` and `/ui/Configuration`; V26–V31 `/ui/nowPlayingCM`, `/ui/Search`, `/ui/browseMenuGroup`, `/ui/browseGrouped`, `/ui/browseGenres` and `/Shares`; V32–V40 the diagnostics and support pages (`/diag`, `/diagnostics`, `/settings/sendSupportRequest` – only read, nothing is sent), `/Settings?view=web`, `/Dataexport`, `/error?1` (not cleared), `/ui/News`, `/ui/resolveSoviURL` and `/ui/prf` with a read request (`/Volume`); V41–V46 library answers for the response examples of the reference (`/library/v1/Artists`, `Composers`, `Search`, `Albums` with `artist` and with `album` + `artist`, `Folders`); V47 the lyrics of the playing track (`/Info?lyricsid=…`, only when `/Status` has a `lyricsid`, e.g. Radio Paradise); V48–V51 candidates from other BluOS clients: `/diag?print=1` (port 80), `/Settings?expand=1`, `/audiomodes` without parameters and a list of paths that answer 404 (V51; `/Mute`, `/ZoneStatus`, `/Players`, `/Sources`, `/GroupStatus`, `/PlayQueue`, `/CoverArt`, `/RadioDeletePreset`, `/Search`, `/RadioSearch`, `/captures`, `/ui/reportServiceDuration`). V52–V55 check findings of `tests/tools/crawl-endpoints.js`: `/Playlists` with `sort=recent` (same playlists as `sort=alpha`), `playlist=<name>` (only that playlist) and an unknown name (`not found`); `/Presets/edit?prid=…` answers 405 to GET (V53); the web page `/services` on port 80 with its links to the sign-in pages, 404 on port 11000 (V54); the context menu of the first TuneIn favourite station with and without `is_preset` and `inputType` (V55, skipped without one). Not called: `/ui/prf` (runs a request), `/ui/action` (changes the display), `/ui/clearUsageHistory` (deletes the history). Answers go to `fixtures/verify-*`.

### 2 Write (changes the player)
- **C01–C47** (commands): every command the app uses: favourite, play album, pause, resume, skip, back, play queue entry, seek, add to queue, remove from queue, shuffle on / off, repeat (queue / track / off), volume (level, ±dB), clear, save / load / delete playlist. The queue is saved as `__bluos_album_player_test__` at the start and loaded again at the end; favourite, repeat and volume are restored, the test playlist is deleted. It also checks that the playlist id (`/Playlist` id = `<pid>` of `/Status`) changes after add, remove, shuffle on / off, clear and load – the app reloads the queue only on this change. The favourite and album commands (C05–C09, C22–C25) use the album of A07 and A09: when folder 2 runs alone, they are skipped.
- **W01–W15**: moves the first queue entry and back (`/Move`), stops (`/Stop`), loads the next preset (`/Preset?id=+1`), skips on the radio station if it offers a skip action (`/Action`), returns to the former queue entry and position (`/Play?seek=…&id=…`), pauses again if it was not playing and restores the volume.
- **W16–W29** (run after S52, `seq` 115–128): parameters of `/Add`, `/AddFavourite` and `/DeleteFavourite` found by `tests/tools/crawl-endpoints.js`. W16 saves the queue as playlist `__bluos_verify_add__`. W17–W22 run the `autoplayURL` of the first favourite song (`category=FAVOURITES`), of a song of the first composer (`composer=`) and of the first song on the second page of the saved queue playlist (`offset=`, skipped with 10 queue entries or fewer) and check with `/Status` that this song plays. W23–W26 favourite a composer song that is no favourite yet with the `/AddFavourite?fn=…` of its context menu, find it in the favourite songs, remove it with `/DeleteFavourite?fn=…` from that list's menu and check that it is gone. W27–W29 load the saved queue, return to the former entry and position, pause again if it was not playing and delete the playlist. Every URL comes from `/Browse`; skipped when the player does not play from the queue. Answers go to `fixtures/verify-add-*.xml` and `fixtures/verify-*-favourite-song.xml`.
- **W30–W33** (`seq` 129–132, independent of W16): favourite the first library artist that is no favourite yet with the `/AddFavourite?artist=…` of its context menu, find it in the favourite artists (Library › Favourites › Artists), remove it with `/DeleteFavourite?artist=…` from that list's menu and check that it is gone. Answers go to `fixtures/verify-*-favourite-artist.xml`.
- **W34–W37** (`seq` 133–136, independent of W16): move queue entry 0 to position 3 (`/Move?new=3&old=0`), check the order (entry 0 taken out and inserted at index 3, a new queue `id`), move it back (`/Move?new=0&old=3`) and check that the order is as before. Skipped with fewer than 5 or more than 200 queue entries.
- **W38** (`seq` 137, independent of W16): favourite the first library playlist that is no favourite with the `/AddFavourite?playlistid=…` of its context menu, find it in `category=FAVOURITES`, read the menu with `&isFavourite=1` appended to the key (as the app does), remove it with its `/DeleteFavourite?playlistid=…` and check the menu offers `favourite-add` again. Skipped without a library playlist.
- **S01–S35, S41–S52**: reads a setting, changes it, checks the new value and restores it: indicator brightness (`/setting`), replay gain (`/audiomodes`), balance (`/alsa_setting`), trim of a fixed group member (`/SlaveVolume`, skipped without a fixed group). Reads through `/proxyToSlave`, the playlist backup `/download_playlists_api`, `/redirectToCp`, the web pages `/wificfg` and `/triggercfg` and `/Info?infourl=…` (only when the playing item has an info URL). Saves the queue as test playlist `__bluos_verify__`, adds an album with `/AddToPlaylist` and deletes the playlist; renames the player with `/Name?set=` and back (S31–S35); switches the listening mode (`/alsa_setting?preset=`), checks with a `/Status` long poll whether the etag reports it, and back (S41–S47); checks whether `/Shuffle` without `state` switches shuffle off, and restores it (S48–S52).

### 3 Manual (run on purpose)
Every request is skipped unless `runManual = true`. Set it, run the folder (or a selection of requests) in the Runner, set it back. A request sent on its own (Send) is not skipped: `bru.runner.skipRequest()` works only in the Runner, so it then goes out without its parameters (e.g. a bare `/DeleteFavourite`).
- **M01**: doorbell chime (`/Doorbell`; players without a chime answer `Not supported`).
- **M02–M03**: library rescan (`/Reindex`); it runs in the background for minutes.
- **M04–M06**: stores a test preset `__bluos_verify__` (`/SetPreset`). No request to delete a preset is known – remove it in the BluOS app.
- **M09–M12**: saves a backup of the playlists (`/download_playlists_api`, to `fixtures/verify-playlists-backup.json`), uploads the same backup again (`/upload_playlists_api`) and checks that the playlists are unchanged. Needs `saveFixtures = true`; the upload is skipped without a fresh backup.
- **M14–M18**: switches the statistics collection (`/statistics?enable=0|1`, port 80) and back, read from the diagnostics page. While it is on, the player may send usage statistics to Bluesound.
- **M19–M20**: rebuild index (`/delete_index`, port 80) – the library index is deleted and the whole library is scanned again; then `/Status`.
- **M21**: `/UpdateDNS` (answers empty, no visible effect; purpose not known).
- **M22**: `/RadioAddPreset` adds TuneIn station s16252 as URL favourite `__bluos_verify__`; M24–M26 remove it again.
- **M23**: `POST :80/playurl` plays TuneIn station s16252.
- **M24–M26**: find every `__bluos_verify__` in the TuneIn favourites (category "Url", `preset_id` `u…`; also copies left by earlier runs), remove them with the `/DeleteFavourite?id=u…&service=TuneIn` of their context menu and check that none is left.
- **M27–M30**: favourite the first local TuneIn station that is no favourite (`/AddFavourite?preset_id=…` from its context menu), find it in the TuneIn favourites, remove it with `/DeleteFavourite?id=…` and check that it is gone. The favourites are stored in the player's TuneIn account.
- **M31–M34**: the same for the first station of Radio › Most popular stations (Airable): `/AddFavourite?service=Airable&url=…`, the station is marked `is_preset=1` in the list, `/DeleteFavourite?…&url=…` removes it. Without a login to the radio service the player answers `Login to use favourites`; M32–M34 are skipped then. Answers go to `fixtures/verify-*-favourite-{url,tunein,airable}.xml`.
- **M13**: clears the recent stations (`/ui/clearUsageHistory?stations=1`) – the history is lost.
- **M07–M08**: soft reboot (`POST` to port 80 `/reboot`), then waits until `/SyncStatus` answers again (at most 5 minutes) and logs how long the restart took.

## Fixtures
With `saveFixtures = true` every request stores its answer in `fixtures/` (next to this README). The folder is ignored by git: the answers contain details of your network and library (IP addresses, share names, room name).

To use them for the UI tests, copy them without personal details (from the repository root):

```
node tests/tools/sanitize-fixtures.js
```

`23-api-version.xml` and `24-bluos-version.xml` record which player software the answers come from (API version from `/Version`, BluOS version from `/GitVersion`).
